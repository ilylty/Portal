# Portal 许可证校验与二开合规说明

本文档用于说明本项目当前的许可证校验方式、相关文件位置，以及二开前的合规准备事项。

## 1. 当前项目如何做许可证校验

结论：仓库内**没有发现本地自动化许可证校验任务**（例如 Gradle 许可证扫描插件、CI 中的 license check workflow）。

当前可见的“校验/声明入口”主要有两类：

1. **源码仓库许可证文件声明**
   - 通过根目录 `LICENSE` 声明主许可证（Apache License 2.0）。
2. **外部平台状态展示**
   - `README.md` 中包含 FOSSA 徽章链接，用于展示第三方平台的许可证分析状态。

## 2. 许可证与相关信息位置

### 2.1 主许可证文件
- 路径：`LICENSE`
- 内容：Apache License 2.0 全文。

### 2.2 README 中的许可证说明/入口
- 路径：`README.md`
- 位置：
  - 文件头部和底部包含 FOSSA 状态徽章
  - `## License` 小节
  - 中文说明中提到 Apache 2.0 的使用条件

### 2.3 需特别注意的第三方代码许可证头
以下文件头部显示来自 LSPosed 的 GPL 许可证声明（GNU GPL v3 or later）：
- `xposed/src/main/cpp/elf_util.h`
- `xposed/src/main/cpp/elf_util.cpp`

这表示仓库内至少存在 Apache 2.0 与 GPL 相关代码并存的情况，二开发布前必须进行许可证兼容性与分发策略评估。

## 3. 二开前建议的合规准备清单

1. **先做许可证清单盘点（必做）**
   - 逐模块梳理：自研代码、第三方库、拷贝/改写代码。
   - 形成“组件-版本-许可证-来源链接”台账。

2. **明确分发边界（必做）**
   - 确认 GPL 相关源码是否进入最终分发产物。
   - 若进入分发，按 GPL 要求提供对应源码与声明。

3. **补齐分发材料（必做）**
   - 在发布包/仓库中保留并附带：
     - 原项目及第三方的版权声明
     - 对应许可证文本（至少 Apache-2.0、GPL-3.0）
     - 修改说明（你二开后改了什么）

4. **建立自动化校验（强烈建议）**
   - 在 CI 增加许可证扫描与阻断策略（例如依赖许可证白名单/黑名单）。
   - 将结果固化为可审计报告，避免仅依赖 README 徽章。

5. **发布前法务复核（强烈建议）**
   - 对商用场景、闭源场景、再分发场景分别评估风险。

## 4. 一句话结论

本项目当前主要依赖 `LICENSE` 文件声明与 README 中的 FOSSA 链接展示状态；仓库内未发现内建自动化许可证校验流程。二开前应重点处理 Apache 与 GPL 共存代码的合规分发问题。
